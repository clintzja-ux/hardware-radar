# EDR-029 — Consolidate routine publication into canonical Sentinel execution

**Status:** Accepted

**Date:** 2026-11-22

**Scope:** Forge Newegg routine, Mercury terminal classification, Sentinel publication invocation

## Context

The production routine certified a candidate but selected publication authority from a fixed environment value through a separate post-success wrapper and receipt. That duplicated canonical authority selection and created a second handoff boundary. Separately, any intermediate `REPLAY` or `NO_CHANGE` could incorrectly classify a run with meaningful final Current or History changes as `SUCCESS_NO_CHANGE`.

## Decision

Use the existing canonical publication authority repository to select exactly one enabled, currently valid production mandate with available daily allowance. Bind the certified candidate to the originating routine, pass the selected mandate identity directly to the existing Sentinel publication command, and let Sentinel retain every publication eligibility, authority, Git, deployment, acceptance, and recovery decision.

Retire the normal-path fixed environment mandate selection and post-success publication receipt. Preserve historical evidence as immutable data rather than continuing its writer. Derive routine change/no-change from the authoritative final Current and History evidence, not incidental replay classifications. Present one of five operator outcomes while retaining detailed underlying evidence: `LIVE_ACCEPTED`, `SUCCESS_NO_CHANGE`, `RELEASE_READY_NOT_PUBLISHED`, `ACQUISITION_FAILED`, or `PUBLICATION_FAILED`.

Standardize subprocess invocation on the canonical environment file and system CA. Introduce no new coordinator, journal, authority, ledger, or recovery path.

## Alternatives considered

- Patch the configured mandate ID: rejected because it preserves duplicate authority selection and will fail again at mandate rotation.
- Keep the post-success receipt as an orchestration gate: rejected because Sentinel already owns the durable publication operation and recovery evidence.
- Move publication policy into Mercury or Forge: rejected because Sentinel remains the canonical publication owner.
- Automatically retry failed publication: rejected because ambiguity and failure-specific recovery must remain operator-governed.

## Consequences

- One Forge action can complete the ordinary acquisition-to-acceptance lifecycle.
- Missing or ambiguous mandate eligibility fails before Sentinel execution as `RELEASE_READY_NOT_PUBLISHED`.
- Publication failures retain Sentinel evidence and remain recoverable only through existing classified recovery procedures.
- Historical post-success receipts remain readable but no new normal-path receipts are created.
- Production acceptance requires one ordinary integrated run to prove exact candidate binding, canonical Sentinel ownership, governed checkpoint/deployment handling, and an authoritative operator outcome without a parallel handoff.
