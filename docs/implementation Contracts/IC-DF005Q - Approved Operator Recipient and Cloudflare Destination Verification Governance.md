# IC-DF005Q — Approved Operator Recipient and Cloudflare Destination Verification Governance

Source-controlled approval `beacon_gateway_operator_alert_recipient_approval_v1` records `OPERATOR_APPROVED` for one operator-controlled operational-alert destination without storing its address. Approval, runtime configuration, verification, provider deployment, sender/domain readiness, and sending authority are independent. Approval does not set `BEACON_ALERT_RECIPIENT`, configure a Worker, or authorize delivery.

Production remains address-free: the DF005-P runtime map is empty, DF005-O projects `NOT_CONFIGURED`, verification evidence is absent, and sending is false. A valid server-side runtime fixture projects `PENDING_VERIFICATION`. Only `CloudflareDestinationVerificationEvidence` bound to the same configured address and `BEACON_ALERT_RECIPIENT` may project `VERIFIED`; the evidence contains authority, verified state, opaque provider destination reference, and verification time. The address remains private runtime comparison material and is excluded from evidence serialization. Missing, malformed, wrong-authority, wrong-key, browser-supplied, or mismatched evidence fails closed.

`GatewayAlertRecipientReadiness` exposes only governance metadata: operator approval, runtime mechanism availability, runtime presence, verification state/evidence presence, provider selection/deployment, sender/domain state, alert and notification policies, sending state, transport, and browser connection. It never returns the address. Production is `OPERATOR_APPROVED`, runtime not configured, verification not performed, provider undeployed, sender/domain unconfigured, sending disabled, Gateway `RUNTIME_SELECTED`, transport `NOT_CONNECTED`, and browser disconnected.

Cloudflare destination verification remains an explicit later operator action. Provider evidence may be recorded only after Cloudflare reports a non-null verified time for the matching destination. Email Sending domain onboarding, the destination-restricted `send_email` binding, provider deployment, and sending enablement remain later independent decisions. DF005-Q performs no verification request, email, Cloudflare API call, resource creation, deployment, browser connection, acquisition, or spend.
