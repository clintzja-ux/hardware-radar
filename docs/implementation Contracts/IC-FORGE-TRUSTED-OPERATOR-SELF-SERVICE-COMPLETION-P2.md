# IC-FORGE-TRUSTED-OPERATOR-SELF-SERVICE-COMPLETION-P2

Forge's loopback-only trusted operator runtime composes the existing Atlas catalog administrator, Mercury production destination owner, manual-current-price affiliate workbook, bounded link verifier, and durable operator audit. It creates no canonical subsystem.

The runtime supports registered-manufacturer selection or evidence-backed Atlas registration, DRAFT RAM product creation, permitted product edits, governed retailer destinations, exact-product link checks, and Newegg affiliate add/replace/disable/history. Affiliate writes preserve the workbook schema and unrelated entries, retain a digest-addressed prior copy, serialize writers, revalidate the workbook digest immediately before atomic replacement, and remain independent of market ranking, eligibility, Current, History, Picks, and Cheapest.

Product Manager is rebuilt from canonical owners on each trusted local request, so successful mutations become visible without a manual export. Manual projection import remains diagnostic fallback. Search, filters, and selected-product context remain browser state.

## DRAFT correction and destination workflow amendment

Broad product-name, classification, capacity/module, physical, compatibility, and supported specification corrections are authorized only for an unbound `DRAFT` / `PENDING` record. Atlas product ID, manufacturer, MPN, governance, provenance, revision order, schema, duplicate detection, and capacity equality remain invariant. Existing destinations make a broad correction ineligible; ACTIVE products retain the narrower established edit scope.

Retailer choice is projected from Atlas's active registered-retailer owner. Forge extracts Amazon ASIN or Newegg commerce identities from an exact HTTPS product page, while Mercury remains responsible for URL canonicalization, exact binding, replay, collision, supersession, serialized/atomic retention, and audit ordering. For Newegg, `/p/<id>` is retained as product-page identity and an explicit case-insensitive `Item=<id>` is retained separately as the offer/listing identity used by established Mercury acquisition owners. They are not required to match. Known tracking parameters alone may be removed; duplicates, malformed Item values, and unsupported query semantics fail closed. Path-only legacy records remain readable and are never silently assigned an Item identity. A DRAFT destination is retained for operator workflow but remains explicitly non-public and grants no market or publication authority.

An eligible `DRAFT` / `PENDING` product may append exactly one validated HTTPS manufacturer evidence source through the existing Atlas edit owner. The prior evidence array must remain an exact prefix, the new source ID must be unique, and operator identity, revision, single-writer lock, schema validation, and atomic product-file replacement remain mandatory. Product ID, manufacturer, brand, MPN, governance, and unrelated provenance cannot change through this amendment. ACTIVE records remain ineligible. A bound DRAFT may correct evidence, but the result explicitly requires operator revalidation of its existing destination; no destination is silently changed or retired.

Product creation remains DRAFT. No generic canonical Atlas readiness/activation owner exists for this runtime, so Forge exposes no activation control. Link reachability never establishes exact-product identity and never retires a destination automatically.

All certification writes use disposable fixture copies. Production Atlas, destinations, workbook, Current, History, publication, release, and deployment remain outside fixture certification.

## Runtime retailer and affiliate management correction

The trusted launcher identifies the Git revision loaded by the active loopback runtime and replaces a stale local process before opening Forge. The Product Manager projection must contain valid canonical retailer records; missing or malformed retailer data blocks link controls with an explicit recovery message instead of rendering an empty selector. Human-readable retailer names are displayed while canonical retailer IDs remain the control values.

Manage Links separates the governed retailer destination from affiliate routing. Retailer URLs continue through Mercury destination validation and exact listing identity. The existing manual-current-price workbook owner alone supports Newegg affiliate add, replace, disable, stale-digest protection, single-writer locking, atomic replacement, recoverable prior copies, and trusted audit history. Unsupported retailers expose no affiliate Save action. The bounded verifier may check saved retailer URLs; it does not claim affiliate-network health verification. Successful changes reload canonical projection state immediately. Affiliate routing remains independent from identity, Current, History, Cheapest, Picks, recommendations, and retailer eligibility.

Saved-link verification is an audited read distinct from destination retention. Every click carries a new request identity, optional `www` host aliases compare as the same approved retailer, reachability never proves exact-product identity, bot/network blocking reports unavailable rather than broken, and repeated checks never create, replace, or retire a destination. Existing destination replay conflicts remain mutation safeguards and are not link-health outcomes.
