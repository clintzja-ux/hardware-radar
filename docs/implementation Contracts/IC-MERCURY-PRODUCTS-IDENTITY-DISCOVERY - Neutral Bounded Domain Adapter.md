# IC-MERCURY-PRODUCTS-IDENTITY-DISCOVERY — Neutral bounded domain adapter

## Status

Production composition fixture-certified. `createProductionProductsIdentityDiscoveryService()` assembles the neutral coordinator, SQLite repository, canonical readiness owner, Atlas, rights, spend, task/execution/consumption, immutable result, Google, and Amazon owners. The production lifecycle and its separate taskless-authority reconciliation commands are exposed as thin operator commands. Command availability is not execution authority.

## Canonical readiness owner

`ProductsIdentityDiscoveryReadinessOwner` accepts only an Atlas product ID, supported source ID, and explicit assessment time. It derives Atlas existence, current source rights, and source-native identity state. Google resolution is delegated to `GovernedProviderIdentityResolver`, which validates admitted-history/evidence/task lineage and returns reusable, absent, or conflicting-review state. Amazon resolution is delegated to the acceptance artifact and effective acceptance-action projection, including H051 reassessment and H052 operator confirmation. Retailer destinations never become identity authority.

The canonical states are `READY_FOR_DISCOVERY`, `ALREADY_RESOLVED`, `REVIEW_REQUIRED`, `RIGHTS_BLOCKED`, and `UNSUPPORTED`. An H052-eligible `INSUFFICIENT_ASIN_EVIDENCE` outcome remains `REVIEW_REQUIRED`; it does not authorize redundant discovery. The deterministic readiness binding covers product, source, state/reasons, identity references/digests, current rights digest, and policy version. The explicit assessment time is reported separately and does not create false drift when governed identity and rights remain unchanged. This makes the projection suitable both for PREPARE selection and START drift detection without creating economic or execution authority.

The Google neutral-lineage finalization boundary is an additive progression variant in the existing H034 canonical result/progression repository. It binds the exact neutral plan, run, member, parent and child authority, H032 artifact, provider task, canonical result, product, rights, progression input, and unchanged output from `createProductsIdentityProgressionOwner()`. It does not reinterpret identity. Successful resolved material becomes visible through the existing `GovernedProviderIdentityResolver`; review-required, ambiguous, and unusable outcomes remain fail-closed. The production factory supplies that resolver with the canonical neutral-finalization repository, so a durable `NO_USABLE_IDENTITY` result projects `REVIEW_REQUIRED` instead of silently becoming another paid-discovery candidate. Exact replay returns the same finalization, while changed lineage or result material conflicts.

Exact-MPN Google Products discovery is an observable, governed corroboration source, not the default unresolved-SKU identity route. A successful provider response does not establish reusable identity: noisy product-family results promote only when the certified matching rules produce strong, contradiction-free identity. A terminal non-usable result must not be blindly rediscovered without new evidence and a future explicit governed reset or new-cycle justification. No matching threshold is changed by this source-role rule.

## Boundary

`ProductsIdentityDiscoveryDomainAdapter` is the typed domain adapter over `NeutralBoundedPaidActionCoordinator`. It derives deterministic member identity from source, Atlas product, and explicit discovery cycle; asks an injected canonical identity owner for current readiness; delegates source preparation, child authorization, execution, task resolution, retrieval, and identity finalization to existing Google or Amazon owners; and stops when the Products identity outcome is durable.

It owns no parent authority, aggregate budget, transport, rights registry, task ledger, provider-result repository, or identity interpretation. Google uses `PRODUCTS` with a `$0.001` ceiling. Amazon uses `AMAZON_PRODUCTS`, its required acceptance-artifact lineage, and a `$0.0015` ceiling. Destination ASINs remain corroboration only.

## Complete production source owners

`createProductionGoogleProductsDiscoverySourceOwner()` composes the production Products PREPARE owner, neutral-derived child authorization, H032 artifact handoff, single-use task execution, exact plan/execution/task resolution, Products retrieval, H034 canonical result persistence, `NeutralGoogleProductsFinalizationService`, and the existing Products identity progression owner. `createProductionAmazonProductsDiscoverySourceOwner()` composes product-scoped acceptance preparation, the immutable acceptance artifact, neutral-derived Amazon action authority, `AmazonAcceptanceExecutionService`, canonical task and execution ledgers, H047 retrieval/result persistence, H051 processing/effective projection, and the previously certified pre-execution recovery boundary. H052 is exposed only as review availability and is never executed automatically.

The production factory reads checked-in destinations through canonical `loadRetailerDestinationSource()` validation and adapts its validated records to the Amazon owner's existing `getAll()` dependency. It does not use the private indexed `FileRetailerDestinationRepository` schema for the checked-in source. Destination validation, effective-head and supersession semantics remain with the canonical loader; destination ASINs remain corroboration and cannot bypass H051 or H052.

Both constructors are product-generic and use repository lookups keyed by exact durable lineage. They add no product-specific policy, repository, queue, workflow engine, retry authority, Sellers transition, or downstream write authority. The canonical rights profile digest is derived from the complete registry profile when the registry does not expose a precomputed digest; revalidation recomputes that same digest and continues to fail closed on drift.

## Lifecycle

PREPARE accepts only an explicit cycle and `atlasProductId`/`sourceId` cohort pairs. Only `READY_FOR_DISCOVERY` members enter paid scope. INSPECT is read-only. AUTHORIZE creates one expiring neutral parent for the exact ready set. START revalidates identity and rights, derives one source-owned child per member, and delegates at most one Products task per member. A bounded member cannot enter recoverable `AUTHORIZED` state unless its exact child execution authority is durably persisted and content-bound.

For Google Products, the complete neutral-derived authorization request is stored in the existing immutable H032 PREPARE-artifact repository before the neutral child reference and `AUTHORIZED` checkpoint. The H032 artifact binds the parent, plan, member, product, source, operation, rights, task ceiling, child authority, expiry, and exact execution request, and is indexed by parent authorization/member. Exact replay returns the same artifact; changed immutable material conflicts. Amazon retains its equivalent durable authority in the existing acceptance-action repository rather than duplicating it in H032.

PENDING becomes `WAITING_FOR_PROVIDER`; RESUME normally reuses the recorded task and cannot add authorization or scope. Pre-execution recovery is permitted only for an already-existing immutable source-owned child authority. Google resolves its exact H032 artifact. Amazon resolves the exact neutral child reference and delegates validation and task-first recovery to its existing durable acceptance-action owner. Both paths check for an existing exact provider task or completed execution before permitting the same unconsumed child to execute once. Recovery creates no parent or child authority, never renews expiry, and cannot broaden product, source, operation, rights, cost, or retry scope. Missing, consumed, expired, malformed, or substituted authority and parent/member/source/operation/product/rights/cost/digest conflicts fail closed as systemic integrity failures. AVAILABLE results go to the existing source identity owner. Product-local ambiguity, insufficient evidence, review-required, no-result, and ordinary provider failures do not become systemic failures. Rights, parent/child, budget, task-persistence, immutable-result, repository, or systemic-transport integrity failures stop the run.

The production Amazon recovery composition checks the exact canonical task ledger and execution ledger before execution. An existing task or completed execution is returned without another provider call. Only when neither exists, the original action remains unconsumed and unexpired, and every neutral parent/member/child/artifact/rights/cost/retry binding matches may that same authorization complete its original provider execution once. Concurrent calls through the production owner are serialized and converge on one canonical task. A consumed authorization without recoverable task or execution lineage fails closed. No successor or replacement authorization is created.

Multi-member execution recognizes daily-spend progression only through `BoundedSpendProgression`: the exact bounded parent authorization/digest, plan/digest, run, authorized member, durable child authority, provider task, canonical execution row, actual cost, member ceiling, parent aggregate, and zero-retry rule must agree. The coordinator remains sequential. Spend from member 1 and cumulatively from members 1–2 can therefore satisfy later child plans prepared at the original snapshot, while unrelated or interleaved spend cannot. The canonical execution ledger and `readGovernedSpendForUtcDay` remain the sole spend owners, the `$0.025` ceiling remains enforced, and non-bounded acquisition retains exact snapshot matching.

## Expired consumed taskless child disposition

`TasklessChildAuthorityDispositionService` records the terminal audit fact `EXPIRED_CONSUMED_WITHOUT_TASK`; it grants no authority. Qualification requires exact bounded parent, plan, run, member, child, immutable source-owned authorization, and single consumption lineage; expired authority; an `EXCEPTION` member with `paidTaskCreated=false`; and authoritative absence of canonical task, execution, and result. Google absence is resolved from its deterministic request key and H032 artifact. Amazon absence is resolved from its acceptance artifact, request digest, and paid-action intent. Unsupported, ambiguous, unconsumed, unexpired, pending, task-producing, recoverable, or result-bearing lineage fails closed.

The bounded SQLite repository owns the additive content-addressed disposition because it already owns the neutral child reference. The record binds the original authority and incident, assessment, expiry, consumption, source/product/operation, operator, reason, and immutable digests without rewriting the parent, child, run, member exception, or source artifact. Exact replay is duplicate and changed material conflicts. Recording runs under the canonical acquisition single-writer lock and repeats the task/execution/result checks while serialized against paid execution; a concurrent task or recoverable execution prevents disposition. The old child is never renewed or reused. Any future discovery requires a new cycle, readiness assessment, plan, parent review, and child authority.

Disposition-aware continuation preserves already-paid work without reopening expired authority. On RESUME, `recoverMember()` validates and terminally skips an `EXPIRED_CONSUMED_WITHOUT_TASK` exception before calling any source recovery owner. The original exception and disposition remain unchanged. A `WAITING_FOR_PROVIDER` sibling with an exact canonical task bypasses child execution and continues only through result reuse/retrieval and identity finalization; parent/child expiry prohibits new execution but does not strand an already-created task or its canonical result. PENDING replay remains waiting on the same task, AVAILABLE material finalizes through the existing neutral Google owner, and a pre-existing canonical result avoids provider retrieval. No new task, authorization, spend, Sellers, evidence, history, or current/public authority is created.

The read-only assessment command is `mercury:identity-discovery:assess-taskless-disposition`. The append command is `mercury:identity-discovery:dispose-taskless` and requires operator, non-empty reason, and confirmation `DISPOSE-EXPIRED-CONSUMED-TASKLESS-CHILD`. Neither command creates paid, retry, replacement, Sellers, evidence, history, current-price, or publication authority.

## Terminal separation

The terminal boundary is Products identity only. `STRONG_UNIQUE_ASIN` and `INSUFFICIENT_ASIN_EVIDENCE` remain exact Amazon owner states; the latter may expose H052 review availability but creates no H052 confirmation. No Sellers task, evidence, historical fact, Current Price, Current Display, Cheapest, Pick, recommendation, publication, or affiliate authority is created.
